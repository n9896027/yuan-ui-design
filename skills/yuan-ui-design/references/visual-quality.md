# Visual Quality Without Template Slop

在做视觉升级、设计系统、落地页、后台、编辑器，或从截图、竞品、视频提炼界面范式时读取本文件。

## 从参考中提炼，不复制

先拆解参考的可复用关系：

- 页面骨架与阅读顺序；
- 空间比例、密度和留白节奏；
- 字体层级、数字排版和内容宽度；
- 色彩角色、表面层级和对比策略；
- 组件如何表达状态、优先级和可点击性；
- 动效承担的解释、反馈或方向感；
- 参考里不适合当前产品的部分。

不要复制品牌标志、独特插画、专有文案、图标组合、像素级布局或受保护组件。最终设计必须能从当前产品的任务、内容和品牌中解释出来。

确实采用外部参考时，分清它解决的**问题**、可迁移的**机制**和有来源辨识度的**表达**。“用连续轨迹表达阶段关系”是机制，具体配色、字体、图形和文案组合是表达。选一条有用的机制，说明怎样服务当前任务；其余决定从自身内容与设计系统推导，不靠设计师名字代替分析。

在已有笔记或交付说明中简述来源、采用的机制和本次自己的表达即可。声称看过参考前要实际查看原图或页面；没有测量就不填精确比例。完成后并排检查：若只是把来源换了产品名，保留有用关系，重做表达。不强制另建参考报告。

## 先选产品结构

不要从“高级 UI”反推统一壳层。按任务决定：

- **Dashboard**：优先异常、决定和下一步，而不是把所有数字平铺成卡片。
- **Editor/tool**：画布、对象、属性、历史和执行反馈围绕编辑循环组织。
- **Landing page**：先建立价值、证据和可信度，再安排转化；不要用假产品截图充当证明。
- **Learning product**：围绕观察、操作、反馈、解释和迁移组织，不让导航压过学习对象。
- **AI product**：AI 只在确有能力时出现，展示来源、范围、不确定性和用户控制；不默认右侧聊天栏。

## 一句话视觉概念

用“产品隐喻/材料感 + 信息节奏 + 用户情绪”描述方向，并说明理由。例如不是“高级深色科技风”，而是“像工作台一样直接：纸面注释层承载解释，机械刻度承载可调参数，让学习者看见因果”。

概念必须约束实际决定：字体、色彩、密度、组件形状、图像、动效和反馈。若删掉概念后设计毫无变化，概念就是空话。

骨架重做时，再看用户是在远看识别还是近看核对，内容的容量与节奏，以及对象本身的时间、空间、尺度或连接关系，指出它如何形成一项可见决定。时间线、地图、刻度或场景只是候选；精确核对与高密度扫描仍可采用列表/表格，不强套视觉隐喻。

## 先发散，再收敛（只用于高视觉新建或大改版）

当新建产品表面、主品牌语言或页面骨架要重做时，先用真实代表内容做 2–3 个轻量方向。它们至少在信息密度、叙事隐喻或布局骨架之一上不同；每个方向说明怎样帮助主任务。选定方向后，再完成可操作纵切并做字距、间距、颜色和文案的局部调整。

方向可以来自题材、已实际看过的同媒介参考或另一种内容组织方式，不凑固定来源或随机配额。每版简述任务入口、骨架、主要视觉材料、由内容形成的可见决定和取舍。实施中需要判断视觉时，用同样内容、视口与相近素材完成度做代表首屏/关键状态的可见对照，不能只给风格名称或色板；无需每版扩成完整产品。

仅交设计规格时，也用几句方向草案或小线框保留比较与选择理由；不要求实现多个成品或另写方案报告。已选方案应体现一个具体方向，不能只罗列风格名称。

小修、已获认可的品牌或明确设计稿，直接沿用既有方向；不要为了发散而制造替代方案。方向比较是帮助判断的草案，不替代真实交互和状态验证。

用户要求选择后再执行时，展示后等其选择；已有方向、用户要求自行判断或当前授权足以继续时，说明取舍后推进，不把方向比较变成额外审批点。

## Art direction 与素材

为关键页面明确选择视觉材料，而不是把留白、渐变或一张无关配图当成风格：

- 真实产品、真实场景或可授权资料能提供证据时，优先使用并保留其来源边界；
- 需要不可得的氛围、概念、纹理或插图时，可生成与视觉概念一致的素材；生成图不得伪装成产品证据、用户成果或真实数据；
- 图解、流程、数据关系和可交互反馈优先用原生代码、SVG、Canvas 或真实组件构成，使其可访问、响应且可验证；
- 任务文字保持代码原生的可读文本，字段和按钮保留语义、焦点与输入路径；自定义画布提供等价可访问路径，不把任务控件烘焙进图片。

素材的授权、付费生成、外部上传和发布仍遵从当前任务的授权边界。素材只证明视觉，不能证明功能或数据真实。

先区分内容证据、解释材料与氛围装饰。具名产品、真人、真实地点或文物依赖真实/已授权素材，不能用生成替身冒充；数据、结构和流程则可由原生代码表达。内容确需图片时，先确认关键图片的来源、可用性、裁切与图注，再定图文骨架。无关 stock 图、emoji 和色块不能冒充必要图片，也不为避免纯文字而强加配图。

必要素材缺失时，明确影响哪项设计判断或交付，继续能独立完成的部分；未补齐不声称完整高保真。素材归属或复跑确需记录时，沿用已有路径、来源/许可、用途及生成边界，不默认新建资产数据库或扫描私密目录。

## Design grammar

建立一套足够小的语法：

- semantic colors，而不是按页面随意命名；
- 标题、正文、标签、数字、代码和辅助文字的层级；
- spacing scale 与内容密度；
- control、surface、overlay 的 shape/depth；
- focus、selected、warning、error、success 的状态语言；
- motion duration、easing 和 Reduced Motion 行为；
- 数据可视化的轴、图例、单位、缺失值和不确定性。

已有系统时扩展；不要为一次改版制造第二套平行 tokens。让生成或实现先理解真实组件、props、variants、可组合方式、实际模式（如主题、密度、语言）及已验证的页面示例，再决定新增什么。若有 Figma 或其他设计源，按需记录其变量/组件与代码 token/组件的来源映射；没有该来源时不要强制补建。需要交换格式时，DTCG token 应使用显式 `$type` 与 `$value`，但是否迁移由项目收益决定。语义 token 优先表达用途；少量原始值可以存在于基础层或有理由的局部实现中。

## 排印从阅读任务推导

先区分连续阅读、数据核对、操作 UI 与展示标题，再看中文/混排/西文构成，据此决定行长、行高、层级与密度，最后选字体和实际可用字重。沿用已有字体规范，不为“独特”额外下载字体或替换全站字栈。用最终长度的真实内容检查：

- 长中文段落的回行，标题孤字、专名与标点断行；
- 中文、拉丁字符、编号、日期和金额同排时的视觉大小、基线与间距；
- 长 URL/英文、单位和多位数字的容器边界；需要逐列核对时，检查数字对齐与精度，适合时采用等宽数字；
- 强调所用字重/字形是否存在，合成斜体或加粗是否损害中文可读性；优先调整字形、字重或语义强调，不用全局位移修补正文；
- 字体不可用、加载中或回退时是否仍可完成任务；新增 webfont 按 [accessibility-performance.md](accessibility-performance.md) 检查加载与布局变化。

断行、字体特性、合成限制和子集化是按字体与目标环境选择的实现手段，不照搬固定字号比例、字体黑名单、引号样式或中英空格偏好。

## 真实内容

- 使用产品领域的对象、单位、长度、错误和权限边界。
- Mock 数据要形状真实、量级合理，并明确是 Mock。
- 文案先解决任务，再塑造语气；避免“解锁未来”“无缝赋能”等抽象承诺。
- 中文与英文分别检查自然语序、术语密度和长度，不把一种语言机械挤进另一种布局。
- AI 输出不夸大能力；来源、时间、范围或置信边界在需要时可见。

## 视觉辨识度检查

完成一轮后问：

- 如果去掉 logo，这仍然像这个产品吗？
- 是否有一处由产品任务自然产生的独特视觉或交互记忆点？
- 是否所有内容都被包成同样卡片？
- 是否因为“AI 产品”而机械使用紫蓝渐变、光晕、网格和聊天气泡？
- 主要动作是否被英雄图、3D 背景或装饰抢走？
- 高密度界面是否仍有明确分组，低密度界面是否仍有足够信息？
- 状态差异是否只靠颜色？

发现模板化时，先重做信息架构或产品隐喻，不用再加一层特效掩盖。

把常见生成痕迹当作复核信号，不是风格禁令：出现奶油色衬线、酸绿点缀、报纸式细线、超大圆角、玻璃模糊或紫蓝光晕时，检查相应选择是否服务概念、内容和可读性。能解释就保留；不能解释就替换为更贴近产品的决定。

## 截图批评

截图用于发现视觉问题，不证明交互或上线状态。至少对比：

- 首屏阅读顺序；
- 主要 CTA 和当前状态；
- 对齐、基线、间距和密度；
- 文本换行、截断和数据单位；
- 桌面与移动重排；
- focus、error、empty、loading、success 等关键状态；
- 参考范式与最终原创设计的差异。

把差异写成“问题 -> 用户影响 -> 修正”，不要只写“更高级”“更现代”。

高视觉任务先复核概念是否留下结构、材料或阅读顺序的后果，再看字距、对齐等细节。换成一个相近题材后，哪些决定必须改变？没有可指出的差异时，重审内容组织；局部产品修复不要求发明独有视觉母题。

长页面按有代表性的真实视口/关键区段查看，不能只缩小整页长图判断文字和间距。每轮保留一项有效决定，再选少量影响最大的实际问题先修：先结构与素材，后细节。改后重看受影响范围；范围内已无待修问题就停止，不为凑轮数制造改动或日志。任务需要审阅/复跑时再保留首轮与最终对照。

整页没有横向溢出，不代表局部表格、长名称或状态已可读：检查被截断的对象如何确认、局部滚动是否可发现，以及主要操作是否仍能定位。局部修复后用 diff 清理无关的版式、标题与文案变动。

窄屏数据界面按任务选择：保留有理由的二维局部滚动，或将每项重排成带字段标签的条目；不要把所有表格一律改成卡片。身份、状态和操作若是当前任务必需，就要有完整可读、可到达的路径；重排不能复制一套隐藏但仍可聚焦的控件。桌面紧凑度与手机可读性分别检查。

需要成品校准时，按相似任务选读 [visual-case-library.md](visual-case-library.md)。样例用于理解层级、密度和状态后果，不是可套用的配色或页面皮肤。
