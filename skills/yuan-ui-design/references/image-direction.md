# 配图方向与可追溯来源

只有当图片能比文字和界面结构更清楚地说明主体、尺度、材质、场景、对比或下一步操作时才使用。先写清主体与裁切意图：焦点是什么、小尺寸下必须保留什么、目标比例，以及允许舍弃哪些边缘。

插画、概念场景、纹理和非特定人物，优先使用宿主已授权的 ImageGen 工作流。记录生成方式、提示词/简报版本、所用模型或工作流与主体。若任务需要可识别的真实产品、地点、作品、人物或历史对象，不要生成摆拍替身；应取得授权的真实图片，或明确说明不可得。不要把此工具强制用于纯图片生成任务。

## 选出能完成任务的那张图

先拿一个最难的画面试排。设备辨认页应同时看见目标接口和相邻接口，两者的相对位置帮助判断；影片节目单应在最窄的卡片上保留能认出该片的动作或构图。把候选放进实际组件，在手机首屏和桌面详情中各看一次。若主体已被标题、遮罩或裁切挡住，换构图、换图，或为该视口单独取景。为准确辨认产品时，优先保留原始比例，热点绑定图片坐标；加载失败时仍应能通过名称和位置继续。

为带叙事的界面制作插画时，先确定一张主图的视角、光线、笔触和色域，再沿用这些约束制作后续画面。每张图各自承担一个信息任务，例如交代环境、呈现动作、解释结果。将整组图缩到最终显示尺寸并排检查，确认读者仍能区分步骤、识别同一主体。图片承载的信息写进替代文本，纯装饰图可用空替代文本。关键标题仍用真实界面文字，便于调整、翻译和放大。

## 取得并交付素材

外部摄影或档案图必须有可复核的具体来源。Wikimedia Commons 只适合已选定具体 `File:` 文件页的图片，并应记录作者、署名、许可和文件页；宽泛网页搜索只是发现线索，不等于可复用授权。不要抓取付费、私有或来源不明的图片。

对获授权本地资源或已选定 Commons 文件，在放入交付物前可运行工具。公开 sidecar 默认不写入本机绝对路径；用可审阅的资产登记号、工单号或已批准的相对引用代替。
工具唯一的额外依赖是 Pillow，用于在写出前真实解码并拒绝截断、伪装和超大图片：`python3 -m pip install Pillow`。

```bash
python3 skills/yuan-ui-design/scripts/image_provenance.py import-local \
  --source /absolute/approved-image.png --dest assets/approved-image.png \
  --source-reference 'asset-registry:2026-kettle-01' \
  --author '项目摄影组' --license '项目内已授权使用' \
  --subject '拉丝不锈钢水壶，侧面' \
  --focal-intent '4:3 裁切中保留壶嘴和把手' \
  --rights-note '已取得本项目页面使用授权'

python3 skills/yuan-ui-design/scripts/image_provenance.py fetch-commons \
  --title 'File:Example.jpg' --width 1600 --dest assets/example.jpg \
  --subject '图片中可见对象' --focal-intent '完整保留主体，不裁切'
```

sidecar 记录模式（`mode`）、来源（`source`）、作者、许可、生成/取得方式、主体、焦点或裁切意图、SHA-256、字节数和可识别时的尺寸。`--width` 请求 Commons 的同文件缩略图；省略时取原图，并分别记录有效的 `original_url`、`download_url` 与取得方式。工具拒绝覆盖、拒绝未知尺寸或伪图片；图片和 JSON 都先写同盘临时文件，再以不可覆盖的原子操作发布。遇到 HTTP 429 会显示 `Retry-After`；严格等待它，不要频繁重试。需要替换时，使用新的目标文件名并更新引用。

将图片与 `.provenance.json` 一起保存。哈希仅证明复核后的文件未变化，不证明所有权、法律充分性、事实准确性或使用适配性。发布前重新打开来源页、履行许可要求（包括署名与相同方式共享），并确认 sidecar 中没有不应公开的内部信息。
