# Existing Repository Integration

已有仓库中的 UI 修复、改造或接入现有状态时读取。新原型、纯规格与没有代码库的任务不需要这条流程。目标是沿用系统完成用户任务，验证深度仍按 SKILL.md 的改动能力选择。

## 先建立最小事实链

只检查改动需要的入口和消费者，确认：

| 事实 | 可复核的来源 |
|---|---|
| 运行入口与构建 | package/scripts、路由、实际进程工作目录及本地响应 |
| 组件边界 | 真实 props、事件/回调、父状态、已有复用点 |
| 视觉来源 | 当前 tokens、CSS module/组件变体、品牌与语言 |
| 数据身份 | 对象/书籍/任务 ID、缓存或存储 key、数据形状 |
| 状态与持久化 | 初始化/恢复、内存、实际提交、失败、重试与重进 |
| 本次范围 | 可改文件、不会触及的接口、原有工作树改动 |

从代码和实际运行中区分“已有事实”与“本次提议”。没有 API 的本地功能不补造服务端；已有组件不重写为一页独立演示来冒充集成。小改动可直接在工作记录中说明这些事实，不强制建立报告或扫描整个仓库。

## 保护现有工作与环境

- 检查工作树与项目约定。用户要求隔离、仓库存在并行改动或评测需要冻结时，使用 worktree 或范围明确的副本；记录它是否包括用户当前改动，不能以 HEAD 冒充当前工作树。
- 只带入所需源码、构建配置和获准使用的材料。不要为运行 UI 复制凭据、会话、浏览器资料、私密文件或历史输出；缺少必需能力时说明真实边界。
- 依赖与缓存也有写入范围。若复用依赖，确认构建缓存和生成文件不会写回受保护的原目录；不为一次局部修复升级框架或重装无关依赖。
- 本地预览绑定适当的本机地址，复用任务拥有的会话；核对绝对资源 URL、外部服务与可能产生副作用的接口。可用本地同一资源验证时记录替换范围，不把替换后的结果说成外部服务通过。
- 重启并验证本任务拥有、受改动影响的预览进程，避免测试旧 bundle。结束按 verification.md 清理自己的浏览器和服务，保留用户会话。

## 对接同一个 source of truth

画出必要的一条真实链，例如：

```text
原生文件选择/现有组件回调
  -> 父组件按对象 ID 更新内存字段
  -> 已有存储或请求确认
  -> 可见反馈
  -> 重新进入后按同一 ID 读回
```

分清组件正在显示、当前会话保留、提交已确认和恢复已完成。不同持久化区域（例如 localStorage、sessionStorage 或服务器）分别判断，不用一个 catch 或“保存成功”覆盖全部边界。

涉及自动保存或恢复时，特别检查：

- 初始化尚未读取完成、确实没有记录、读取受阻和格式损坏不能混为“空”。未读/损坏的现有记录不能被默认空状态静默覆盖。
- 只在实际写入确认后声明已保存。写失败保留当前编辑，并给出与真实能力相符的恢复路径；不把“页面仍能用”当作已持久化。
- 恢复后重试应使用最新对象身份和当前编辑，保留未改字段与其他对象。按字段还是整条记录合并、冲突如何处理，服从现有数据语义并让后果可理解。
- 刚设置某个 UI 状态，不代表同一事件的下一步已读到新值或已提交。实际断言恢复之后的数据源与重进结果，避免只看提示从 error 变成 ready。
- 保留组件身份与用户输入。回调和批量状态更新要基于有效的当前状态，避免旧闭包覆盖同轮其他字段；具体实现沿用仓库的状态设施。

这些是相应能力的边界检查，不要求每个页面实现存储、冲突系统或保存按钮。

## 先证明改动，再扩大检查

1. 对已报告问题，在原始构建中建立最小复现；若是新增能力，记录当前限制，不能编造原版缺陷。
2. 在候选的真实路由与组件链运行任务，核对 DOM 与实际存储/请求；适用时包含失败、恢复、切换对象、刷新或重新进入。正常页面打开和构建通过都不能替代主链。
3. 优先使用自然可控条件，如合法的小测试文件或任务浏览器内实际耗尽存储配额。替身响应、API 覆盖、调度或断网注入要标明，不冒充真实外部服务或设备验证。
4. 使用原仓库必要的类型、lint、构建和相关测试。状态/接口改动查其消费者；样式改动查受影响视口与控件。手写 ambient 类型和构建通过不能证明第三方运行时 API 存在，必要时核对已安装版本及资源创建/释放的实际所有者；不为填覆盖数制造无关测试。
5. 对照 diff，去除无关改造；记录失败、修复与未测项。做首次交付评测时先冻结首版，再单独保存后续修复；普通产品任务不必为此额外建立评测系统。

## 交付边界

提供可运行结果、必要改动位置、复现/验证方式与限制；需要用户审阅或迁移到主项目时，再给出最小 patch 和组件/状态说明。隔离副本的成功不等于原项目已更新，也不等于生产已部署。

真实应用的本地链可标 local-runtime；替身依赖、故障注入和外部未验证部分分别说明。已有应用与局部修复的前后对照不是两个技能版本的因果评测。

React 实现中，Effect 与外部系统同步及状态更新时机可按目标版本核对官方 [useEffect](https://react.dev/reference/react/useEffect) 与 [useState](https://react.dev/reference/react/useState)；这些文档不替代实际仓库契约。
