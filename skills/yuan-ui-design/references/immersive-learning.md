# Meaningful Immersive Learning

用于让学习者通过操作理解因果、约束或策略的教学与训练任务。面向观察、配置或导航的产品 3D 见 [spatial-product-ui.md](spatial-product-ui.md)。

## 先证明为何需要空间

只有当空间关系、因果变化、尺度、顺序、路径、约束或实体操纵本身有助于学习时，才使用 2.5D/3D。若平面图、排序、表格或普通表单能更直接完成任务，优先简单形式。

以下不是充分理由：

- “更酷”或“更像游戏”；
- 需要一个动态背景；
- 把选择题散落在三维房间；
- 让用户走到按钮前再回答同样的问题；
- 只有镜头旋转、卡片漂浮和粒子反馈。

## 互动学习闭环

每个核心装置都应形成：

```text
观察 -> 操作 -> 世界/模型变化 -> 即时反馈 -> 解释 -> 可迁移判断
```

有效模式包括：

- 重组对象后，系统行为或约束立即改变；
- 调整参数后，多个候选结果、分布或轨迹发生可比较变化；
- 在资源约束下搭建方案，容量、安全或质量后果实时显现；
- 检查空间中的证据并形成决定，遗漏会在后续状态中产生可理解后果；
- 失败后保留过程，让学习者定位具体因果并重新尝试。

评分或“答对了”不能是唯一反馈。界面应让学习者看见为什么变化、哪些边界仍未被证明，以及如何把判断迁移到新情境。

## 3D 不得成为任务壁纸

对每个 3D/2.5D 元素问：

1. 用户能操作什么？
2. 操作改变哪一个真实学习状态？
3. 世界如何响应？
4. 响应揭示了哪条因果或约束？
5. 测试如何断言，不只比较截图？

任何问题无答案时，删除、降级为装饰，或重新设计为有后果的装置。相机移动属于导航，不自动算学习互动。

## 输入与降级

- 拖拽对象必须有选择后放置、移动按钮或其他单指非拖拽路径。
- 键盘用户要能进入场景、辨认对象、操作、退出，并看见焦点。
- 触控不能依赖 hover、右键或精细命中。
- Reduced Motion 下取消眩晕式位移、视差和持续旋转，保留必要状态反馈。
- 无 WebGL、低性能设备或资源加载失败时，提供结构化 2D 视图完成同一核心学习目标。
- 降级路径操作同一个任务状态与评估逻辑，不做一套无关的简化选择题。

## 状态、评估与 Replay

- 将探索性操作与计分/提交边界明确分开。
- 评估读取学习者真实构建、路径或参数结果，不只读取最后一次按钮选择。
- 完成条件应绑定可解释的约束；失败反馈指出具体因果，不泄露内部安全细节。
- Replay 若用于比较策略，应保留旧结果只读，并为新尝试建立独立状态。
- 需要确定性比较时，固定输入、规则和随机种子，并记录版本；视觉随机效果不得影响评分。
- 存储、渲染库和模拟器实现必须先映射现有技术栈；IndexedDB、WebGL、具体公式或文件结构只能标为提议，不能在未检查仓库时写成既有事实。

## 验收矩阵

实现后按交付宿主和实际学习机制选取检查。纯规格只写验收方法：

- 指针、键盘，以及面向触屏用户时的触控主链；
- 一次有效构建、一次失败/修正和一次重新尝试；
- Reduced Motion；
- 无 WebGL 或资源失败降级；
- 面向网页时验证所支持的代表性视口，原生或头显按目标宿主选择设备；
- 状态/DOM/API 断言证明装置改变了真实学习状态；
- 资源加载、长任务、布局稳定和持续动画成本。

仅能操作镜头、只有视觉变化或最终仍靠选择题通过时，结论必须是“沉浸表现存在，但核心互动未通过”。
