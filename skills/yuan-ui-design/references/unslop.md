# Unslop · 既有界面视觉精修

适用于用户指出一张已有界面「有 AI 味」「太像模板」，或直接要求 unslop。先识别这张屏幕上值得保留的设计，再决定改动幅度。用户只要审查时，交付定位与理由即可。

## 先看屏幕，再选改动幅度

有源码时，从真实入口打开代表状态，记下窗口、主题、语言、内容和操作位置。只有网址时，先观察实际页面；如果交付的是本地静态改稿，标清原站与改稿。只有截图时，可在图上定位或制作注明来源的静态重构。响应、焦点、提交和持久化都需要在相应宿主另验。

沿用户视线找出影响最大的几个位置。对每处写清「哪里／谁会遇到什么问题／哪项改动能验证」，同时指出一个要保留的产品决定。渐变、emoji 和圆角只是线索。品牌中的渐变、区分告警等级的颜色、用户写进内容的表情，都可能有明确作用。

| 画面证据 | 执行动作 |
| --- | --- |
| 找不到影响识别、理解或操作的具体问题 | 说明哪项设计已服务任务，结束这次审查。 |
| 问题集中在几个控件、文案或局部状态 | 按原有组件与品牌修正，逐项重看受影响的状态。 |
| 多个区域在争夺注意力，用户难以辨认主要内容或操作 | 简述谁在做什么、产品应给人的感受，以及哪个真实内容最值得突出。选一个与这个领域有关的细节贯穿相关视图，再做整屏调整。 |

整屏改稿可以用五行确定方向：使用者和任务、产品气质、材料或场景依据、值得看清的一两处内容、能反复帮助识别的细节。例如在维修台，技术员需要辨认刚才保存的是哪张工单。工单号与设备名可构成稳定的起读位置，错误说明放在原草稿和重试动作旁。如此即使拿掉品牌名，读者仍知道下一步该做什么。

视觉润色默认沿用功能、数据、信息顺序和导航。用户已经授权实施时直接推进；用户指定先看方向时，交付审阅稿后再继续。仅修保存逻辑、键盘错误或数据丢失时走原有功能修复流程。

## 只有网址时，先验证可编辑副本

选定一个具体页面和首屏尺寸。想调整手机首屏时，直接取手机尺寸。需要对比两个断点时，为两个尺寸分别建目录。运行环境需要 Node.js、Playwright 及 Chromium，从已安装 Playwright 的项目目录执行下列命令。将技能目录换为当前安装路径。

```sh
node "${CODEX_HOME:-$HOME/.codex}/skills/yuan-ui-design/scripts/url-baseline.cjs" \
  https://info.cern.ch/hypertext/WWW/TheProject.html --width 390 --height 844 --out baseline-mobile
```

工具只读打开页面，为原屏和回放使用相同的浏览器视口。它向下检查最多三个屏高以触发懒加载，再回到起始位置；更深的内容在清单中仍可能未取到。成功生成清单时退出码为 0，然后用 `status` 判断是否需要复核。

打开 `before.png` 看实际页面，再对照同视口离线打开 `index.html` 得到的 `replay.png`。先读 `manifest.json`，识别字体替换、延迟出现的图片和动态图层。显示 `needs-review` 时，在原图标出受影响的内容：图片能否辨认、标题有没有换行、Canvas 里哪一层只有一帧或已经缺失。只在可复现的区域比较设计改动；交互、提交和实时渲染仍须回原宿主验证。

保留这份原始基线，复制整个输出目录后再编辑副本里的 HTML 或静态素材。按原来的尺寸与滚动位置重拍改稿，用前后的截图进行离线审阅。像素一致说明在记录的环境中复现了该画面；设计是否改善，要回到具体的阅读或操作任务判断。

## 按问题分层修改

大范围精修可依次检视 **间距、颜色、图标、文案、排印、布局、控件细节、配图、动效**。只处理诊断命中的层，必要时回看相邻层。比如改短标签后，在手机上重看按钮宽度和焦点；把状态底色收敛后，重看报错时文字和操作是否仍容易找到。

- **分组与层级**。比较组内和组间距离，检查重复行的起点、数字与单位。把注意力留给当前对象、数值或主要动作。已有语义色、图标名、品牌字和触控目标应按产品需要保留。
- **语言与排印**。把抽象口号换成已有事实或具体动作。中文用真实长名称试排。双向文字界面按目标语言核对图标方向、前进返回和数字混排。
- **视觉重点**。营销页可以让实物或场景解释价值；数据后台可让异常区间和比较基准成为焦点；编辑器常常只需突出当前对象、草稿或失败位置。需要识别实物时用[配图与选图](image-direction.md)核对来源与裁切。
- **反馈与收尾**。动效应说明状态如何变化；减少动态效果后仍须看得出结果。沿原有动作从输入走到反馈，必要时再走一次失败、重试和重开。对已有仓库的保存行为使用[旧数据保护方法](repository-integration.md)。

## 判别模板感

在具体的屏幕上试一次替换：换掉照片、对象名或产品名，哪些主标题、编号、文案和装饰还可以原样套到另一个行业？检查它们是否帮助读者辨认内容或完成操作。需要删减时，优先让出位置给真实材料与决定所需的信息，并保留已经有效的品牌表达。

比较两版时，分别记录第一眼能否认出这个项目、哪一处让人理解具体材料、哪个控件真的值得使用。醒目的标记要对照原物核准；界面中的动作还要亲自操作。交接单或清单上新增的「待办件数」也要在完成一项后重看，确认它与已完成计数一致。截图偏好和任务成功可以指向不同的版本。

## 将结果交给审阅者

在相同内容、视口、主题和状态下重看原图与改稿。长页对准同一段，错误态对准同一次错误。说明哪个问题解决了、依据是什么、哪些行为实际跑过。像素变化量不代表设计质量。需要交付并排或切换审阅时，可以用本技能的[离线对照工具](../scripts/unslop_review.py)打包现有截图；通常口头审查无需生成文件。

```sh
python3 scripts/unslop_review.py --title "工单保存失败" \
  --pair "手机 · 同一份草稿" before-mobile.png after-mobile.png \
  --pair "桌面 · 同一份草稿" before-desktop.png after-desktop.png \
  --out review.html
```

从技能目录运行。需要 Python 3 与 Pillow。每组使用等大截图，图像内嵌在输出中，可离线打开。图里的姓名、草稿和其他数据会原样进入文件，选取适合交付的样例状态。
