# Rendered UI Case Library

需要校准信息层级、密度或异步交互时，选读一个相似任务。以下来自 2026-11-24 的本地配对实现：同一原始材料、同一资源、每组 60KB HTML 上限、独立执行者。每个版本每项只生成一次，两名独立 Agent 仅看盲化截图；这些是具体案例，不是普遍审美定律或人类认可。

原始任务与 Mock 见 [rendered-evaluation.md](rendered-evaluation.md)。截图来源和哈希见 [provenance.json](../assets/visual-cases/provenance.json)。首轮实现与后续修复分别记录，修复后结果不能冒充首轮成绩。

## 1. 研究入口：视觉叙事需要留下找资料的路径

- [入口较晚的首屏](../assets/visual-cases/research-entry-late.png)：大标题和大图有辨识度，但在 1280×900 桌面首屏里研究列表与筛选未出现。
- [入口更早可见的首屏](../assets/visual-cases/research-entry-visible.png)：图与说明并排，首屏露出研究档案、筛选和研究条目。两名 Agent 更偏好这一任务层级；手机仍需检查入口是否被图文继续推后。
- 可迁移的方法：先用真实标题与摘要检查首屏的任务寻路，再分配视觉叙事的纵向预算。不要把某个固定标题尺寸、左右分栏、奶油底或资料印章当成通用答案。

## 2. 维修编辑：保存可达与草稿保留分别验证

- [失败后保留草稿](../assets/visual-cases/operations-draft-retained.png)：手机编辑区保存动作与长名称分离，失败状态仍保留备注，提供重试。
- 实际浏览器检查覆盖失败不落盘、重试成功、刷新恢复和键盘保存。截图只能支持可见布局与反馈，不能单独证明这些后果。
- 两组页面均通过整页无横向溢出，评审仍发现局部表格截断风险。检查完整对象名、局部滚动可发现性、状态和操作是否能共同识别；不要把输入框正常的单行滚动直接判为数据丢失。
- 局部修复应保留周边系统。更精致的标题或新分组不是修改无关区域的理由；通过 diff 判断每处变化是否服务原问题。

## 3. Agent 工作台：隐藏、部分结果与编辑连续性

- [非预期的首屏弹层](../assets/visual-cases/agent-hidden-overlay.png)：画面显示“尚未生成”却出现空发送确认。浏览器进一步证明隐藏的遮罩仍拦截生成按钮，主链无法开始。代码中的 `hidden` 不是最终计算样式或命中测试的保证。
- [任务原生的初始界面](../assets/visual-cases/agent-task-surface.png)：生成、当前状态、待审阅对象和发送入口围绕协调任务组织。
- [逐项发送结果](../assets/visual-cases/agent-partial-results.png)：两项已确认、一项结果未知，查询入口明确。对应 Mock 状态断言确认 UI 与逐项结果一致；并不证明真实外部发送。
- 首轮新版保留备注值，却丢失输入焦点。单独修复后，焦点、插入点以及跨六次更新的逐键输入检查通过。方法是同时检查值、编辑连续性与状态；恢复焦点的补丁仍不能替代原生 IME 验证，优先保留稳定的编辑控件身份。

## 4. 后续诊断：局部可读性与批量动作

这是首轮之后的定向修复，不是新的独立生成或版本盲评。记录与原始断言见 [followup-provenance.json](../assets/visual-cases/followup-provenance.json)。

- [手机队列修复前](../assets/visual-cases/operations-mobile-before.png)与[字段重排后](../assets/visual-cases/operations-mobile-reflow.png)：原队列在 390px 下只有 372px 可见宽度，内部表格为 630px；整页无横滚仍需要局部横滑。后续按单项工单任务重排，320/390/1280 检查完整字段、逐项编辑和局部宽度；这不意味着所有比较表都应改成条目。
- [手机上的完整工单](../assets/visual-cases/agent-mobile-job.png)：身份、人员/时段、备注和发送结果共同可读。流式实现保留原输入节点，实际逐键输入跨六次更新后，文本、焦点和插入点均保留；截图本身不证明这一行为。
- 原实现取消勾选后编辑另一项会重新选回对象；未知结果可再发一次，Mock 发送计数从 1 变 2；备注中的 `</textarea>` 被当成结构。后续检查验证了选择保持、审阅失效、字面文本和查询不增发送次数。不要从“逐项状态显示正确”推断动作范围和重复执行也已正确。
- 合成组合事件测试曾发现“界面有文字、底层草稿未同步”，修正事件监听后处理器回归通过。它仅测试 DOM 事件处理边界；真实中文输入法、辅助技术、设备触控和外部服务仍未验证。

## 使用边界

参考画面后写出“观察 → 用户影响 → 本产品决定”。根据当前内容和约束重新选择；不复制整套皮肤，不把小样本 Agent 偏好转成分数或全局禁令。正式可用性、屏读、IME、性能或生产结论仍需相应真实环境。
