# 给工具归还页去 AI 味

[原页与两份修订的桌面、手机对照](comparison.jpg) · [原页](original/index.html) · [Huashu Design 3.5.0](huashu/index.html) · [Yuan 2.5.0-dev.4](yuan/index.html)

两位独立制作代理使用相同的模型配置、同一份单文件源码、同一份简报，各只使用指定的设计技能。每方可以自查一次，提交一次。没有外部素材或生成图。这个样例是新的产品任务，两方都没有获得另一方的成品或肖像评审意见。原页带有通用口号、紫色渐变和三张并列卡片。任务要求保留三件工具、三个配件核对项、点交、撤销和刷新记忆。[简报原文](brief.txt)

两位代理评审都看到原页，分别以相反的匿名顺序看两份改稿的桌面和手机截图。他们判断哪份界面更贴合内容，并指出仍可套用的语言或装饰。

| 偏好 | 原因 | 可继续改的地方 |
| --- | --- | --- |
| 评审一选 Yuan | 编号、工具、配件和点交动作在手机上仍属于同一行工单，扫读路径清楚。 | 橙色圆圈和「本班待办」带有通用运营看板的痕迹。 |
| 评审二选 Huashu | 编号优先，核对后再提交，撤销与保存说明都贴着值班流程。 | 「逐件点交，再收工」略像标语；Yuan 的「本班」也超出了已有情境。 |

浏览器验证了两份改稿的键盘点交、刷新恢复、撤销及再次刷新。另查到 Yuan 的主计数会变，但页头写死了「本班待办 · 03 件」，点交一件后仍显示 03。评审看的是初始画面；这项状态不一致保留在盲测首稿中。一次任务和两位代理评审只支持这里记录的偏好。[操作结果](check.json)

在仓库根目录安装锁定依赖和 Playwright Chromium 后，运行 `node benchmarks/return-desk-polish/check.cjs output/playwright/return-desk` 可重拍两种画幅并验证状态。
