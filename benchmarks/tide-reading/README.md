# 潮尺读数复核

[看三版手机截图](comparison.jpg) · [A · dev.4 首稿](tide-a/index.html) · [B · dev.5 首稿](tide-b/index.html) · [C · 据测试修订](revision/index.html)

同一份虚构课程资料提供三个时刻的手写与录入读数。两位独立代理使用相同的模型配置，分别收到旧版与新版技能、同一[简报](brief.txt)和相同的工具预算。每位可静态自查一次，在有浏览器结果前交一次首稿。B 使用的是 dev.5 写入失败复核规则补充前的快照。

两版都把来源和单位放在数值旁。A 用纸质记录簿和连续刻度组织阅读，B 在两值旁补出 9 cm 的差值。匿名代理评审偏好 A 的记录簿层级和时刻定位，同时认为 B 的桌面首屏操作更直接。390 × 844 的手机首屏里，A 和 B 的两种判断操作都在折下，需要向下滚动。评审只看静态截图。

浏览器中，两份首稿均能用键盘及手机模拟触控完成复核，正确更新「已复核／需回查」两项计数，改判和撤销后也能读回。当本机存储拒绝一次写入，两份首稿最终都只提示已标记，未告知改动未保存。刷新会恢复此前成功保存的判断。[原始浏览器结果](check.json)

C 从 B 修订。选中 07:25 时，390 × 844 首屏同时看到 56 cm、65 cm、差值和两个判断按钮。写入失败时显示可见提示，保留当前判断并提供「重试保存」。测试分别验证了失败后刷新读回旧值，以及重试成功后刷新读回本次结果。C 经过诊断和改稿，无法用这份样例推断新版在陌生任务上的稳定优势。

在仓库根目录安装锁定依赖与 Playwright Chromium 后，运行 `node benchmarks/tide-reading/check.cjs output/playwright/tide-reading`，可重跑三版并拍摄桌面及手机版面。
